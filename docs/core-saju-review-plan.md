# 핵심 사주 경험 재설계 + 점신·만세력·포스텔러 리뷰 분석 기획

> 작성: 2026-11-02 · 대상 버전: v0.19~ · 관련 문서: `strategy-v013.md`, `dex-social-competitor-research.md`

## 0. 결론 요약

1. **사주앱을 여는 이유는 "내 운이 지금 어디쯤인가"를 알기 위해서입니다.** 그래서 첫 화면은 기능 목록이 아니라 **오늘 → 이번 주 → 이달 → 올해 → 대운 → 타고난 나**로 이어지는 "운의 타임라인"이어야 합니다.
2. 지금 앱은 기간마다 **계산식이 따로 놀고**, 오늘 운세에 게임 보너스가 **표시 없이 섞여** 있습니다. 내용의 일관성을 위해 엔진부터 하나로 묶어야 합니다(v0.19).
3. 경쟁 앱 리뷰의 3대 불만은 **광고 피로, 기능을 찾기 어려움, 결과의 근거를 알 수 없음**입니다. 3대 요구는 **매일 습관처럼 보는 짧은 운세, 대운·세운·월운을 눌러 보는 깊이, 지난 결과의 저장·확인**입니다.
4. 12지신·부적·성장은 각 운세 화면 끝의 **"한 걸음" 버튼과 수호신 한마디로만** 등장합니다. 메뉴의 주인공이 아니라 답의 후속 행동입니다.
5. 사용자가 원하는 "이번 주 로또 운"은 **재물 흐름 카드 + 재미용 행운 숫자**로 연결합니다. 다만 당첨 암시와 구매 유도는 하지 않고, 안전 문구를 함께 둡니다.

| # | 항목 | 현재 상태 | 문제 | 관련 원칙 |
|---|---|---|---|---|
| A | 오늘 운세 계산 | `fortune.js`: 일진 × 원국 십신 보정 + 합충 + 용신 보너스 + **무작위 ±5** | 대운·세운·월운이 반영되지 않아 **"올해·이달은 좋은데 오늘은 따로"** 노는 구조. 무작위 몫은 근거를 설명할 수 없음 | 일관성 |

| E | 이번 주 운세 | 없음 (v0.18 질문 화면의 7일 그래프만 있음) | 사용자 핵심 수요 누락 | 직관성 |

| G | 올해(신년) 운세 | 월별 리포트와 5년 그래프에 분산 | "올해 총평 → 상·하반기 → 좋은 달" 같은 신년운세 표준 구성이 없음 | 직관성 |

## 2. 설계 원칙: "정통 사주를 먼저, 깊게, 한 목소리로"

### 2-1. 운의 층(Layer) 모델

```
타고난 나 (원국: 일간·오행·용신)
  └ 대운 (10년)      : 지금 인생 계절
     └ 세운 (올해)    : 올해의 주제
        └ 월운 (이달, 절기월) : 이달의 흐름
           └ 주운 (이번 주)   : 7일 중 좋은 날·조심할 날
              └ 일운 (오늘)   : 오늘 할 일 하나
```

### 2-2. 단일 엔진 규칙 (v0.19)

| 층 | 계산 (모두 같은 `periodScore(원국, 간지)` 사용) | 비고 |
|---|---|---|
| 대운 | periodScore(대운 간지) | 10년 단위 |
| 올해 | 세운 0.7 + 대운 0.3 | 입춘 기준 해 |
| 이달 | 월운 0.6 + 세운 0.25 + 대운 0.15 | **절기월** 기준, 기간을 날짜로 표기 |
| 오늘 | 일진 0.6 + 월운 0.25 + 세운 0.15 | 무작위 몫 제거(또는 ±1 이내) |
| 이번 주 | 7일 일운의 평균 + 최고·최저일 | 월~일 고정 |

- 분야별(재물·애정·직장·건강·대인) 점수는 위 점수에 **십신별 분야 보정**만 더합니다(지금의 `TEN_GOD_MOD`를 이 자리로 옮김).
- **같은 날짜는 어느 화면에서 보든 같은 점수**가 나와야 합니다(테스트로 보장).
- 게임 보너스(승천 능력·개운 지수)는 **항상 별도 줄**로 표시합니다: `정통 63 · 수호신 보너스 +4`.

### 2-3. 한 목소리 규칙 (내용의 일관성)

1. **위 층의 키워드가 아래 층 문장에 이어집니다.** 예: "지금 대운은 *배움과 귀인*의 10년 → 올해는 *명예와 인정*의 해 → 이달은 그 흐름이 *재능 발휘*로 이어지는 달 → 오늘은 그 기회를 잡는 날"
2. **모든 점수에 "왜?"가 한 줄씩 붙습니다.** 십신, 용신과의 관계, 합·충을 쉬운 말로 설명하고, 누르면 근거가 펼쳐집니다.
3. **좋은 말만 하지 않습니다.** 조심할 시기도 말하되, 겁주지 않고 행동 하나를 함께 줍니다.
4. **용어 2단계 표기**: 쉬운 말이 먼저, 전문 용어는 괄호나 "전문가 보기"로 보여 줍니다. 예: "윗사람에게 인정받는 해 (정관)"

## 3. 화면 설계: "운의 타임라인"

### 3-1. 첫 진입 흐름

```
생년월일 3단계 입력
  → ★ 나의 사주 한 장 요약 (새 화면)
     · 타고난 나: 일간 한 줄 성격 + 오행 막대 + 필요한 기운
     · 지금 대운: "○○세~○○세, ○○의 10년"
     · 올해 키워드 + 이달 키워드
     · [오늘 운세 보러 가기]  ← 여기서 수호신 소환 연출
  → 홈
```

리뷰에서 가장 많이 보이는 첫 기대("내 사주가 어떤지, 올해가 어떤지")를 **입력 직후 30초 안에** 해소하고, 그다음에 12지신을 소개합니다.

### 3-2. 홈 = 타임라인 카드 (위에서 아래로 시야가 넓어짐)

| 순서 | 카드 | 접힌 상태 (한눈에) | 펼친 상태 (자세히) | 한 걸음 (12지신 연결) |
|---|---|---|---|---|
| 1 | **오늘** | 총운 점수, 한 줄 결론, 행운 색·숫자 | 분야 5개, 근거, 시간대별 조언 | 가장 약한 운 → 부적 받기 |
| 2 | **이번 주** | 7칸 막대, 좋은 날·조심할 날 | 요일별 한 줄, 분야별 최고의 날, **이번 주 재물 흐름 카드** | 좋은 날 알림 받기 |
| 3 | **이달** | 절기월 기간(예: 11/7~12/6), 테마, 점수 | 상·중·하순 흐름, 분야별, 이달의 귀인 띠 | 이달의 오행 채우기 미션 |
| 4 | **올해** | 세운 간지, 올해 키워드, 좋은 달 3개 | 총평, 상·하반기, 분야별 연간, 월별 12칸(정통값 대표) | 고민 해결 30일 여정 |
| 5 | **대운** | 지금 10년의 의미, 다음 대운까지 n년 | 대운 흐름표(전 생애), 지금 대운 안의 세운 10개 | 5년 흐름 + 진화 목표 |
| 6 | **타고난 나** | 일간 성격 한 줄, 오행 비율 | 원국 8글자, 십신, 강약, 용신, 띠 캐릭터 | 내 수호신 보기 |

- 각 상세 화면의 맨 아래에는 **"한 층 위로 / 한 층 아래로"** 이동 버튼을 둡니다(예: 오늘 → 이번 주). 사용자가 메뉴를 고르지 않고도 깊이 들어갑니다.
- 질문형 메뉴(v0.18)는 **분야 축**으로 유지합니다. 기간 축(타임라인)과 분야 축(질문)의 두 갈래가 경쟁 앱의 "카테고리가 안 보인다"는 불만에 대한 답입니다.

### 3-3. 상세 화면 공통 틀 (모든 기간이 같은 순서)

1. 점수(정통) + 한 줄 결론
2. 분야 5개 막대
3. **왜 그런가요?** (근거, 펼침)
4. 시기 그래프 (이번 주 7일 / 이달 3순 / 올해 12달 / 대운 10년)
5. 오늘 할 수 있는 행동 1개
6. 수호신 한마디 (띠 말투)
7. 한 걸음 버튼 1개
8. **📌 기록하기** (나중에 "맞았나요?" 확인)

### 3-4. 탭 구성 (v0.18의 5탭 유지, 역할만 선명하게)

| 탭 | 역할 |
|---|---|
| 🏠 오늘 | 타임라인 홈 (오늘이 펼쳐진 채로 시작) |
| 🔮 운세 보기 | 상단 기간 선택 [오늘·이번 주·이달·올해·대운·타고난 나] + 아래 분야 질문 메뉴 |
| 💬 상담 | 수호신 상담 (지금 층의 운세를 맥락으로 받음) |
| 💞 궁합·친구 | 궁합, 도감, 단톡방 |
| 🐉 내 수호신 | 성장, 부적, 꾸미기, **기록함** |

## 4. 경쟁 앱 리뷰 분석

### 4-1. 조사 방법과 한계

- 대상: 점신(누적 1,500만 다운로드라고 소개됨), 포스텔러(앱스토어 평점 4.6, 평가 약 1.4만 개), 만세력(천을귀인 · 원광만세력)
- **이 작업 환경에서는 앱스토어·구글 플레이 원문 페이지(apps.apple.com, play.google.com)와 일부 블로그(brunch.co.kr, maily.so, m.cafe.daum.net)에 접속할 수 없어**, 리뷰를 인용하거나 요약한 2차 자료(스토어 요약, 기사, 블로그, 커뮤니티 글)를 바탕으로 분석했습니다.
- 그래서 **정량 분석(리뷰 수천 개를 분류한 비율)이 아니라 반복해서 나오는 주제를 묶은 정성 분석**입니다. 아래 수치는 해당 출처가 밝힌 값입니다.
- 원문 수집이 필요하면 환경 설정에서 위 도메인을 허용한 뒤, 최근 1년 리뷰를 수집·분류해 비율을 보강할 수 있습니다.

### 4-2. 앱별 정리

| 앱 | 사용자가 좋아하는 점 | 반복되는 불만 | 우리에게 주는 시사점 |
|---|---|---|---|
| **점신** | 숫자와 그래프로 운세를 직관적으로 보여 줌(GQ). "가장 유명해서 습관처럼 봄". 행운의 번호·코디 같은 매일 콘텐츠. 기본 운세 무료 | **광고 과다**: 신년운세에 30초+15초 광고, "30초 운세에 광고 3분" 같은 후기. 한 분석 글은 과잉 광고 의견이 약 50%라고 집계(2년 전 자료). **기능이 카테고리로 정리되지 않음**(PM다이닝). 입력값이 사라짐·결제 오류 같은 기능 오류. "신년운세가 안 맞는다" | 매일 보는 습관과 숫자 직관성은 배우고, **핵심 운세는 광고 없이** 제공해 차별화 |
| **포스텔러** | 무료 콘텐츠가 넓음. 그래프 구성이 직관적이고 깔끔하다는 평. 점성술·무료 신년운세 평이 좋음 | 사주 정확도는 평가가 엇갈림("사주가 제일 안 맞다"). 맞춤 풀이 광고 길이. 렉·멈춤. 한국어만 지원. 사용한 유료 재화는 환불 불가(약관) | 유료 풀이 전에 **무료 요약이 충분히 깊어야** 신뢰가 생김. 해외판은 다국어 필요 |
| **만세력 (천을귀인)** | 대운·세운·월운을 **눌러 가며 탐색**, 십신·12운성·신살·공망·귀인까지 표시. 기기 저장·백업. AI 해석용 프롬프트 생성 | 튕김·멈춤, 화면이 작음(아이패드), UI 개선 요청, **다른 앱과 결과가 다름**(토정비결), 1900년 이전 출생 조회 불가, 일주 검색 요청 | 깊이를 원하는 사용자를 위한 **"전문가 보기"**와 **계산 기준 공개**가 필요 |
| **만세력 (원광)** | 구글 플레이 약 64만 다운로드, 평점 4.0. "잘 쓰고 있다"는 평이 많음 | 최신 iOS 호환 문제 | 기본기(안정성·호환성)가 평점을 좌우 |

### 4-3. 앱을 가로질러 반복되는 신호

| 신호 | 근거 | 우리 대응 | 우선순위 |
|---|---|---|---|
| 광고 피로 | 점신 리뷰 다수, 포스텔러 풀이 광고 | 오늘~대운까지 **핵심 운세는 광고 없이 무료**. 보상형 광고를 넣더라도 추가 뽑기 같은 **선택형**에만 | P0 |
| 기능을 찾기 어려움 | 점신 카테고리 지적 | **기간 축(타임라인) + 분야 축(질문)** 두 갈래 | P0 |
| 결과의 근거를 모름 / 앱마다 다름 | "앱마다 내용이 같거나 다르다", 토정비결 차이, 대운수 1년 차이 | 모든 점수에 근거 한 줄. **계산 기준 표시**(절입 시각, 야자시, 표준시·서머타임, 경도) | P0 |
| 맞았는지 확인할 방법이 없음 | "신년운세가 맞았는데 확인할 리뷰 기능이 없다" | **운세 기록함 + "맞았어요/아니었어요"** 피드백, 지난 운세 다시 보기 | P1 |
| 타로 결과 저장 | 사용자 조사 요청, 타로 앱의 저장 기능이 장점으로 소개됨 | 신수 카드 결과를 **자동 저장**(날짜·질문·메모), 기록함에서 다시 보기 | P1 |

### 4-4. "이번 주 로또 운" 설계 (안전 장치 포함)

- 이름: **이번 주 재물 흐름** (로또라는 단어는 카드 안의 "재미로 보는 행운 숫자" 설명에서만 사용)
- 내용: 이번 주 재물운 그래프 → 재물운이 가장 좋은 날 → 그날의 행운 숫자 6개(용신 오행 수 + 일진 기반, **결정적 계산이라 다시 봐도 같은 숫자**)
- 반드시 넣을 것
  - "로또는 무작위 추첨이라 운세로 당첨 확률이 달라지지 않아요. 재미로만 봐 주세요."
  - 구매 권유, "당첨 기운", 금액 언급, 구매처 링크 금지
  - 만 19세 미만으로 보이면 숨김(정식 앱에서 연령 확인)
  - 도박 문제 상담 안내: 한국도박문제예방치유원 ☎ 1336
- 연결: "이번 주 재물운을 채우는 부적" 한 걸음 버튼(원칙 3: 결제로 운을 올리지 않음)

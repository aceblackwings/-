## 0. 유사 서비스 조사: "이런 스타일의 앱이 이미 있나?"

### 결론
**사주·부적·캐릭터 육성을 따로 하는 앱은 있지만, 이 셋에 띠 캐릭터 진화·궁합 대화·수집 도감·네온 부적까지 한데 묶은 서비스는 찾지 못했습니다.** 가장 가까운 경쟁자는 "운몽이 점집"입니다.

| 서비스 | 비슷한 점 | 다른 점 | 위협도 |
|---|---|---|---|
| **운몽이 점집** (iOS) | 사주·타로를 보며 **부족한 오행을 채워 주는 "용신" 캐릭터를 키움**. 대화·상담 내용에 따라 불·물·나무·금속·땅 속성 동물로 성장 | 상담·힐링 중심. 띠별 성격, 궁합 대화, 수집 도감, 부적 디자인, 스토리 공유 카드는 확인되지 않음 | **높음** (콘셉트가 가장 가까움) |
| **Chinese Zodiac Horoscope & Pet** (Android) | 내 띠 동물을 펫으로 입양해 습관에 따라 레벨업, 상점과 보상 룰렛 | 서양 시장용 영어 앱. 사주 원국 분석, 궁합, 부적 없음 | 중간 |
| **우주고양이 보라** (iOS) | 고양이 캐릭터가 사주를 풀어 줌. 2년 만에 100만 명 사용이라고 앱이 밝힘 | 캐릭터는 안내자 역할. 육성·수집 없음, 연애 리포트 중심 | 중간 (캐릭터형 사주의 시장성을 보여 줌) |
| **포스텔러 / 점신** | 부적(액막이 부적, 유료 부적) 판매 | 캐릭터와 게임 요소 없음 | 낮음 (단, 자본력으로 따라 할 수 있음) |
| **나를 지켜주는 부적** | 부적 위젯과 매일 운세 | 부적이 장식 위주, 육성·수집 없음 | 낮음 |
| **FortuneMon** (개인 웹 프로젝트) | 운세 결과로 포켓몬을 수집하고 파트너로 교감 | 출시 앱이 아니고 남의 IP 사용 | 낮음 (아이디어 검증 사례) |
| **띠용띠용 동물 친구들** | 다마고치식 동물 키우기와 캐릭터 수집 | 운세 요소 없음 | 낮음 |

### 시사점
1. **"오행을 채워 주는 캐릭터 육성"은 이미 시도된 콘셉트**입니다(운몽이). 그래서 차별점을 다음에 둬야 합니다.
   - **띠별 12 캐릭터 × 성격·말투**와 **144 조합 대화**
   - **친구와 함께하는 궁합·수집 도감** (운몽이는 혼자 하는 상담 위주)
   - **미래형 네온 부적**과 **인스타 스토리 공유**
2. 캐릭터를 내세운 사주 앱(우주고양이 보라)이 100만 명 수준까지 갔다는 점은, **캐릭터형 사주 앱의 시장이 검증되었다**는 뜻입니다.
3. 대형 앱(점신·포스텔러)이 따라 하기 전에 **"친구와 함께 모으는 12띠"라는 소셜 고리**를 먼저 선점하는 것이 중요합니다.

## 2. Q1. 전설의 조합 확장: 어떤 소재가 MZ세대에게 통할까?

### 소재 후보와 평가

| 소재 | 예시 | 장점 | 주의 |
|---|---|---|---|
| **십이지 순서 설화** | 쥐가 소 등에 타고 1등, 고양이가 빠진 이유 | 이미 아는 이야기라 바로 이해됨 | 20쌍 중 일부에 이미 반영 |
| **속담** | 닭 쫓던 개 지붕 쳐다본다, 호랑이도 제 말 하면 온다, 소 잃고 외양간 고친다, 용 꼬리보다 뱀 머리 | 짧고 밈처럼 쓰기 좋음 | 너무 교훈적이면 지루함 → 캐릭터 말투로 비틀기 |
| **전래동화** | 해님 달님(호랑이), 토끼전(토끼·자라), 견우직녀(소) | 세대 공통 기억 | 저작권 문제 없음(구전) |
| **띠별 고정관념 밈** | "용띠는 자존심", "개띠는 의리", "돼지띠는 재물복" | 공감과 놀림이 동시에 → 공유가 잘 됨 | 비하로 흐르지 않게 귀엽게 |
| **세대 밈** | 88 용띠, 95 돼지띠, 00 용띠처럼 출생 연도 + 띠 | MZ세대가 "우리 또래"를 느낌 | 특정 연도 소외 주의 |
| **드라마·예능 패러디** | 유행어 형식만 빌리고 고유 대사는 창작 | 화제성 | 실제 대사·캐릭터 인용은 저작권·초상권 위험 → **형식만 패러디** |

### 추천
1. **속담 10쌍 추가** (가장 효율적): 예) 호랑이 × 아무 띠: "호랑이도 제 말 하면 온다더니… 이 몸 얘기했지? 어흥!"
2. **같은 띠 전용 "출생 연도 밈"**: 같은 띠 친구끼리 띠가 12년 차이 나면 "띠동갑 선후배 대화"
3. **계절 한정 전설 조합**: 설날(소·호랑이), 칠석(소 × 견우직녀 콘셉트), 동지(용 × 뱀)처럼 기간 한정 → 다시 들어올 이유
4. **사용자 투고 대사**: 인기 투표로 채택하면 앱에 실림 (잔망루피처럼 팬 참여형 콘텐츠)

## 3. Q2. 수집 도감이 친구 초대를 얼마나 늘릴까?

### 근거
- 모바일 소셜 게임 연구(PACIS 2014): **게임에 깊이 몰입한 플레이어일수록 친구를 초대할 의향이 높다.** → 도감은 몰입을 만든 뒤 초대를 유도하는 순서가 맞다.
- 모바일 게임 초대 보상 현장 실험(초대자 66,427명, 피초대자 97,181명): **가입해야만 주는 보상**은 초대 수는 적지만 수락률이 높고, **공유만 해도 주는 보상**은 초대 수는 많지만 질이 낮다. → **초대 수와 초대 질의 균형**이 필요하다.
- Co-Star: 친구 차트 비교가 바이럴과 유료 리포트로 이어진 사례.

### 설계 원칙
| 원칙 | 적용 |
|---|---|
| 친구가 가입하지 않아도 칸이 열린다 | ✅ 생일만 입력하면 해금 (초대 장벽 제거) |
| 가입하면 보상이 커진다 | (다음 단계) 친구가 실제 가입하면 "진짜 캐릭터 카드" + 둘 다 인연부 |
| 공유 자체에는 작은 보상만 | 스토리 공유 +20 EXP (하루 1회) |
| 빈칸을 구체적인 사람으로 연결 | "○○띠 친구 찾기" 문구 복사 → 단톡방 |

### 기대 효과 추정 (가정)
- 도감이 없을 때: 궁합을 보는 사용자의 평균 친구 입력 약 1~2명
- 도감이 있을 때: 마일스톤(3·6띠)까지 **평균 3~5명**, 그중 일부가 실제 가입
- 친구 입력 중 20%가 링크로 가입한다고 가정하면, 사용자 1명이 데려오는 신규 가입자(K-팩터)는 약 0.6~1.0
- ※ 위 수치는 실험 전 가정값이며, 베타 테스트에서 "친구 입력 수 / 링크 가입 수"를 측정해 검증해야 합니다.

## 4. Q3. 친구가 가입했을 때 서로의 캐릭터를 방문하는 기능

### 참고 구조: 동물의 숲 "꿈 번지"
- 12자리 코드만 알면 누구나 방문할 수 있는 **열쇠(코드) 방식**
- 방문자는 **구경만 하고 바꿀 수 없음**
- 섬의 **스냅숏(사진처럼 저장된 상태)**을 방문하므로, 주인이 접속하지 않아도 언제든 방문 가능
- 주인이 코드를 **비공개로 바꾸거나 새로 발급**할 수 있음
- 앱 안에 검색·둘러보기 기능이 없고, 코드는 친구끼리 직접 주고받음

### 운명공방 방문 기능 설계안

| 요소 | 설계 | 개인정보 보호 포인트 |
|---|---|---|
| **방문 코드** | "수호 코드" 8자리 (예: `TG-7K2P-QX`) | 생년월일·이름 대신 코드로 연결 |
| **공개 카드** | 띠, 캐릭터 외형·진화 단계, 장착 부적, 칭호, 오늘의 한마디만 공개 | **생년월일·태어난 시간·사주 원국·고민은 절대 공개하지 않음** |
| **스냅숏 방식** | 하루 한 번 공개 카드를 갱신 → 친구가 접속하지 않아도 방문 가능 | 실시간 위치·접속 상태 노출 없음 |
| **방문 상호작용** | 응원하기 1회/일(상대 캐릭터 경험치 +5), 방명록 스티커(정해진 이모티콘만) | 자유 채팅 없음 → 괴롭힘·스팸 위험 낮음 |
| **두 캐릭터 대화** | 방문하면 띠끼리 대화(144 조합)가 자동 재생 | 사용자가 쓴 글이 아니라 정해진 대사 |
| **코드 관리** | 비공개 전환, 재발급, 친구 끊기 | 언제든 연결 해제 |
| **친구 정보 입력 정책** | 친구 생일은 **기기에만 저장**(현재 구조), 서버 전송 시에는 친구 본인 동의 또는 본인 가입 후에만 | 남의 정보를 서버로 보내는 것은 제3자 정보 처리 이슈가 생길 수 있음 |

### 개인정보 관련 유의점
- 이름 등 다른 정보와 결합해 개인을 알아볼 수 있으면 생년월일도 개인정보로 다뤄질 수 있고, 다른 사람에게 넘기면 **제3자 제공** 규정(개인정보보호법 제17조, 동의 필요)을 검토해야 합니다.
- 그래서 **"친구 생일은 내 기기에만, 서버에는 친구 본인이 가입했을 때만"**이 가장 안전한 원칙입니다. 현재 프로토타입은 친구 정보를 기기에만 저장합니다.
- 정식 서비스 전에는 개인정보 처리방침 작성과 전문가 검토가 필요합니다.

### 단계별 구현 순서
1. 공개 카드 + 수호 코드 (서버 필요: 카드 이미지와 최소 정보만 저장)
2. 응원하기·방명록 스티커
3. 방문 시 띠끼리 대화 자동 재생
4. 친구 실제 가입 시 도감 칸이 "진짜 캐릭터"로 바뀌는 연출 + 둘 다 보상

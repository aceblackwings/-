# 결제·출시 방향 메모 (2026-11-04, v0.46)

- 디자인: 매일 쓰는 화면은 파스텔, 유료 풀이는 「한지와 인주」 책자 스타일
- 결제 사다리: 무료 책자(약 4,500자) → 990원 그해 상세판(약 1만 6천 자) · 990원 궁합 상세(v0.46.1) → 4,900원 평생 정통사주(상세판 구매자 3,900원) → 월 구독 3,900원은 출시 3개월 뒤 검토

- 원칙 3 유지: 결제는 읽기만 연다. 점수·부적·지신 성장은 결제와 무관

## 선물하기 · 시즌 할인을 서버 없이 시작하는 법
| 방법 | 어떻게 | 서버 | 한계 |
|---|---|---|---|
| 선물 코드(오프라인 검증) | 코드 묶음을 미리 만들고, 앱에는 코드의 해시와 상품 종류만 넣음. 코드는 스마트스토어 같은 곳에서 「이용권」으로 판매·발송. 받은 사람이 코드를 넣으면 기기에서 해시를 비교해 열어 줌 | 없음 | 같은 코드를 여러 기기에서 쓰는 것을 막을 수 없음 → 저가 상품이라 감수, 묶음을 주기적으로 교체 |
| 대신 열어 주기 | 산 사람이 받는 사람의 생일을 넣어 상세판을 만들고, 한지 책자 이미지·글로 전달 | 없음 | 받는 사람의 동의 필요, 생일은 보내는 사람 기기에만 남김(원칙 5) |
| 스토어 프로모션 코드 | 앱 출시 뒤 App Store 오퍼 코드·Google Play 프로모션 코드로 선물 | 없음(스토어가 처리) | 앱 출시 이후에만 가능 |
| 시즌 할인(앱 안 가격표) | 날짜별 가격표를 앱에 넣음(예: 12/1~입춘 「상세판 + 평생 사주 묶음」 4,900원) | 없음 | 웹 결제는 금액을 서버에서 다시 확인해야 안전 |
| 시즌 할인(스토어) | 스토어 콘솔의 기간 할인 기능 | 없음 | 앱 출시 이후 |

주의: 웹에서 실제 돈을 받으려면 결제 승인 단계에 비밀 키가 필요해 **작은 서버 함수 하나**(Firebase Functions·Cloudflare Workers 등)는 꼭 있어야 한다. 「서버 없이」는 선물·할인 기능이 그렇다는 뜻이다.

## 웹·앱 출시 순서 (추천: 단계형)
1. **웹(PWA) 먼저, 12월 신년운세 시즌에 맞춰** — 지금 앱이 웹이라 가장 빠르다. 웹 결제 수수료 약 3%, 고치면 바로 반영. 준비: 사업자 등록, 통신판매업 신고, 결제 대행사 계약(업종 설명 준비), 결제 승인 서버 함수
2. **안드로이드 앱(2~3월)** — 같은 코드를 Capacitor·TWA로 감싸 출시. 이때 계정(Firebase 로그인)을 붙여 웹에서 산 것을 앱에서도 보게 함
3. **iOS 앱(4~5월)** — 애플 심사 지침 4.3이 운세 앱을 「포화 분야」로 꼽아 심사가 까다롭다. 지신 육성·부적 같은 고유 기능을 앞세워 준비

동시 출시를 권하지 않는 이유: 구매 기록이 지금은 기기마다 따로라, 계정 없이 웹·앱을 함께 내면 「웹에서 산 걸 앱에서 못 본다」는 문의가 생긴다. 계정과 서버가 먼저다.

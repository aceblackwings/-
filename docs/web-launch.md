# 웹 먼저 출시 안내 (v0.65, 2026-11-11)

지금 완성도 그대로 **웹부터** 공개하기 위한 구조와 대표님이 하실 일을 정리했습니다. 앱(안드로이드·iOS)과 로그인·서버 저장은 이 다음 단계입니다(`docs/launch-plan.html`).

## 1. 지금 들어 있는 것

| 항목 | 파일 | 설명 |
|---|---|---|
| 사업자 정보·결제 설정 | `saju-app/js/site.js` | **이 파일 한 곳만 고치면** 바닥글·약관 4쪽에 모두 반영됩니다 |
| 바닥글 | `saju-app/index.html` | 상호·대표·사업자등록번호·통신판매업 신고·주소·고객센터 + 약관 링크 |
| 이용약관·개인정보 처리방침·환불 규정·상품 안내 | `saju-app/legal/*.html` | 글은 `tools/legal_pages.mjs`에서 고치고 `node tools/legal_pages.mjs` 실행 |
| 결제(토스페이먼츠 결제창) | `js/pay.js`, `js/app.js` `openCharmPay`·`resumePay` | 소원 부적 990원 · 100일 소원 등불 2,900원 |
| 결제 승인 함수 | `saju-app/functions/api/pay/confirm.js` | 비밀 키로 토스에 승인 요청. 금액을 가격표로 다시 확인 |
| 출시 전 점검 | `node tools/launch_check.mjs` | 빈 값 알려 줌 + 도메인이 있으면 `sitemap.xml` 생성 |

파는 상품은 **두 가지뿐**입니다(사주·운세·타로·궁합·상세판은 모두 무료). 결제 키를 넣기 전까지는 지금처럼 체험판(결제 없이 만들어짐)으로 동작합니다.

## 2. 결제 흐름

1. 부적 만들기 → 먹 갈기 → 이름 쓰기(여기까지 무료) → 인장을 꾹 → 결제 창(가격·받는 것·환불 제한 고지·약관 링크)
2. 「카드로 결제하고 인장 찍기」 → 만들던 부적을 기기에 잠시 적어 두고 토스 결제창으로 이동
3. 결제 뒤 돌아오면 → 승인 함수가 금액을 다시 확인하고 토스에 승인 요청 → 성공하면 **부적을 먼저 저장**하고 인장 찍는 장면부터 이어서 보여 줌
4. 결제창에서 그만두면 돈은 나가지 않고, 인장 찍기 화면으로 돌아옵니다. 승인 확인이 끊기면 화면을 다시 열 때 이어서 확인합니다(승인되지 않은 결제는 토스가 자동 취소).

결제 회사로 가는 값은 주문 번호·상품 이름·금액뿐입니다. 소원 글·이름·생년월일은 가지 않습니다. 결제 내역(주문 번호·영수증 링크)은 기기에 남고 「환불 규정」 쪽 아래에서 볼 수 있습니다.

## 3. 대표님이 하실 일 (순서대로)

1. **사업자 정보 알려 주기** → `site.js`의 `BIZ`에 넣습니다: 상호, 대표자, 사업자등록번호, 사업장 주소, 고객센터 전화·이메일, (나오면) 통신판매업 신고번호.
2. **도메인 구매**(.kr 또는 .com) → 이름을 알려 주시면 `BIZ.domain`에 넣고 sitemap을 만듭니다.
3. **호스팅 연결 — Cloudflare Pages(무료) 추천**
   - Cloudflare 가입 → Workers & Pages → Pages 프로젝트 만들기 → GitHub 저장소 연결
   - 설정: 프로덕션 브랜치 = 기본 브랜치, 빌드 명령 = 없음, **루트 디렉터리 = `saju-app`**, 빌드 출력 디렉터리 = `/`
   - 연결되면 `https://프로젝트이름.pages.dev` 임시 주소가 생깁니다 → **이 주소로 토스페이먼츠 심사 신청 가능**
   - 사용자 지정 도메인에 구매한 도메인 연결(HTTPS 자동)
4. **토스페이먼츠 가입·계약 신청**: 사업자등록증, 대표자 신분증, 통장 사본, 사이트 주소. 상품 설명 = 「디지털 콘텐츠(소원 부적 990원, 100일 소원 등불 2,900원), 결제 즉시 제공, 오락용」.
5. **시험 키로 먼저 확인**: 토스 개발자센터의 **API 개별 연동 키**(결제위젯 키가 아님)에서
   - 클라이언트 키 `test_ck_…` → `site.js` `PAY.tossClientKey`(저장소에 적어도 되는 키)
   - 시크릿 키 `test_sk_…` → Cloudflare Pages 설정 → 변수 및 비밀 → **`TOSS_SECRET_KEY`**(암호화). **채팅·저장소에 붙여 넣지 마세요.**
   - 시험 카드로 990원·2,900원을 한 번씩 결제해 부적이 만들어지는지 확인
6. **통신판매업 신고**: 토스 계약 뒤 「구매안전서비스 이용확인증」을 받아 정부24에서 신고 → 신고번호를 알려 주시면 바닥글에 넣습니다.
7. **실제 키로 교체**: 심사 통과 뒤 `live_ck_…`·`live_sk_…`로 바꾸고 본인 카드로 990원 결제 → 토스 관리 화면에서 취소까지 해 봅니다.
8. **검색 등록**: 구글 서치 콘솔·네이버 서치어드바이저에 사이트 등록, sitemap 제출.

## 4. 확인이 필요한 점

- **토스 결제창 규격**: 이 작업 환경에서 토스 개발 문서 사이트에 접속할 수 없어, 결제창 호출(`payment.requestPayment`)과 승인 주소는 알고 있는 v2 규격으로 작성했습니다. 5번 시험 결제에서 오류가 나면 오류 글을 그대로 전달해 주세요.
- **기기 저장의 한계**: 로그인이 없어 구매한 부적은 결제한 브라우저에만 있습니다. 사이트 데이터를 지우면 사라집니다(약관·환불 규정·결제 창에 고지, 백업 기능 안내). 문의가 잦아지면 로그인 + 서버 구매 기록(다음 단계)을 앞당깁니다.
- **환불 기준**: 초안은 「오류·중복 결제 전액 환불, 만든 뒤 단순 변심은 제한」입니다. 더 너그럽게(예: 7일 안 무조건 환불) 하시려면 `tools/legal_pages.mjs`의 환불 규정과 결제 창 문장을 바꿉니다.
- **약관·처리방침은 초안**입니다. 회사 정보를 채운 뒤 한 번 읽어 확정해 주세요. 호스팅을 Cloudflare가 아닌 곳으로 하면 처리방침 4번 표의 회사 이름을 바꿔야 합니다.
- 미리보기 전용 기능(AI 상담 `sample`·궁합방·우편함)은 일반 웹에서는 준비된 답변·숨김으로 동작합니다.

## 5. Cloudflare 화면이 Workers로 나올 때 (2026-11-11 추가)

새 Cloudflare 화면에서는 저장소를 연결하면 Pages 대신 Workers 배포 화면이 나옵니다. 이 저장소는 두 방식 모두 됩니다.

- 설정 파일: 저장소 루트 `wrangler.jsonc`, 결제 승인: `worker/index.js`, 사이트에 안 올리는 파일: `saju-app/.assetsignore`
- 화면 입력: 프로젝트 명칭 `zodiac12`(설정 파일의 name과 같아야 함) · 빌드 명령 비움 · 배치 명령 `npx wrangler deploy`
- 배포되면 `zodiac12.계정이름.workers.dev` 주소가 생깁니다.
- 비밀 키: Worker 설정 → 변수 및 비밀 → `TOSS_SECRET_KEY`
- **도메인 연결**: Workers는 도메인이 Cloudflare에 등록돼 있어야 사용자 지정 도메인을 붙일 수 있습니다. Cloudflare에 `ockstar.com`을 추가 → 안내되는 네임서버 2개를 가비아 「타사 네임서버」에 입력 → Worker 설정의 도메인에 `12jisin.ockstar.com` 추가.

## 6. 토스 신청 현황 (2026-11-12)

- 퀵오픈 · 일반 결제 · 카드 + 간편결제(계좌이체·가상계좌·휴대폰 결제는 뺌) · 상품 분류 「사주/운세 > 운세」 · 안심정산플랜 정산한도 월 200만 원
- 시험 키: 개발자센터 → API 키 → 테스트 → **API 개별 연동 키**(`test_ck_`/`test_sk_`). 「주문서형·결제창형 연동 키」(`gck`, 특히 `docs`가 붙은 공용 키)는 쓰지 않음
- 내 상점(MID)이 생기면 그 상점의 키 **세트**로 함께 바꿀 것(섞으면 `INVALID_API_KEY`)
- 승인 함수 보강: 멱등키 · 승인 끊김 시 주문 번호로 결제 조회 · 기기마다 무작위 구매자 번호
